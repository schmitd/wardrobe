# UI contribution contract

These rules preserve Lint's accepted product behavior after regressions in collection selection, removal recovery, authentication, notifications and loading. They apply to changed web flows and their reachable callers. Keep native/mobile contracts and authoritative ownership checks intact. Permanent deletion and Zep retention are outside this contract's implementation scope.

## Reuse the existing surface

| Decision | Canonical implementation | Required behavior |
| --- | --- | --- |
| Choose an owned piece or collection | `OwnedPiecePicker`, inline named collection buttons in `CollectionsWorkspace`, inside the current `TaskSheet` | Show image/label choices directly; no native entity `<select>` or browser prompt/confirm, and no redundant chooser/drawer before the task. Native file/library pickers, camera permission, geolocation consent and install affordances remain valid. Dialogs and ordinary preference controls remain valid when justified by the task. |
| Add a photo | `CaptureMenu`, `WebPhotoCamera`, `UnifiedCapture` | Keep the direct accepted entry and cancel/back path; preserve platform photo and camera behavior. |
| Recover removed data | Account route `/account/data`, `DataManagement` | Keep removed collection/inspiration browsing here. Immediate action-triggered Undo remains in context. Orchestrate necessary collection restoration safely; do not show an unavailable/prerequisite state alongside a false empty result. Show one actionable message at the point it matters; preserve required privacy consent without repeating helper paragraphs. |
| Notice during a task | `Notifications`, host in shared `ui/dialog`, `TaskSheet` | Notice belongs in the active focus scope and can be dismissed there. Routine success expires with the existing interaction/visibility pause policy; errors and Undo persist until handled. Adding z-index over an inert drawer does not make a notice accessible. |
| Display generated or stored outfit prose | `outfitText`, planning boundary validators | User-facing text and accessible labels contain human names, not transport/model IDs. Keep IDs in transport, keys and private data attributes. Preserve implicit wear policy and contextual permissions; avoid new wear/readiness/reason questionnaires. |
| Auth, data and owner boundaries | `AuthEntry`, `HomeSectionBoundary`, `AppIdentityScope`, `Providers`, `WardrobeShell` | Render public geometry while auth/query results are unresolved. Empty requires resolved data and appropriate pagination coverage; errors need an actual request/remount/reload retry. Unmount private UI and cancel late callbacks on owner/session changes; safely partition resumable owner-bound drafts and keep them hidden from guests/other owners. Preserve settled same-owner content on navigation. Suspense for modules does not resolve an undefined Convex subscription. |
| Loading and images | `RackItemCard`, `WardrobeShell`, shared layout geometry, `StyleNotes`, Plan/Diary layouts | Reuse settled structure, spacing and reserved image area; avoid approximate skeleton dimensions or invented item counts. Reserve cutout image dimensions without an opaque rectangle pretending to be the garment; retain the actual card frame and text/status indicators. Palette remains stable across mount/image decode. Measure delayed query and image transitions against representative loaded cards; unknown content length cannot promise zero shift. |
| Provider/account controls | `GoogleCalendarConnect`, account controls in `Providers` | Distinguish selected, authorized, reading, available and failed using observed state. Preserve editable drafts on failed/canceled authorization. Check actual Clerk controls for contrast, keyboard focus and return focus. |

## UI-change checklist

Record evidence for the actual changed entry and its reachable paths; mark a path inapplicable with a reason instead of claiming an untested pass.

- Exercise entry, selection, cancel, Back/Escape with return focus, error, successful retry and reload. Include pending→content/known-empty/error, same-owner navigation, sign-out and owner/session switch. Verify retry changes the failed boundary and selection/cancellation does not cause unintended writes.
- Run relevant real-component tests and `bun run validate ux`; add a minimized regression at the affected boundary with a legitimate positive control. Mock external services only, not the component whose behavior is being claimed. Test the current caller, not a hand-built lookalike.
- Capture changed mobile surfaces at 320/390/430px and a desktop viewport: pending and settled cards, delayed images, open tasks and recovery. Record header/rail/card/Plan/Diary bounding boxes, overflow and deltas; for layout-shift measurements state the no-recent-input window and unavoidable content-length changes. Use production CSS.
- Record text/icon contrast and visible focus/return-focus evidence for changed controls, including actual hosted Clerk controls when touched. Distinguish synthetic browser evidence from provider/live/device evidence. Include revision, commands, artifacts and remaining coverage gaps in the PR.

## What the gates prove

`apps/web/validation/ux-eslint.mjs` is wired into the existing required web lint. Its AST checks reject native selects with recognized entity option IDs or entity list maps; direct IDs in JSX prose and accessible labels; literal removed/archive browse calls in `CollectionsWorkspace`; and browser prompt/confirm calls in the named entity surfaces. Negative fixtures in `ux-eslint.test.ts` prove each refusal and positive fixtures preserve file/camera permissions, generic preference selects and Undo. This is syntactic coverage: aliases, dynamic argument construction, indirect/generated prose and newly named domain concepts still need review. Do not claim absolute prevention.

Existing test discovery runs `OwnedPiecePicker.test.tsx` against the real picker/sanitizer. `DataManagement.test.tsx` covers restoration/query/owner semantics; `DayPlanner.calendar.test.tsx` covers provider truth/draft/permissions. Existing browser gates exercise active notice hosts/expiry, task focus/geometry, delayed Home/auth, retry and owner continuity. Loading/Plan/Diary changes must extend those real-component probes with measured geometry; copy brevity, unnecessary task steps, actual provider styling and visual quality remain human acceptance requirements. No word-count or broad text-grep gate substitutes for them.

Exceptions require a precise surface, rationale, preserved interaction/ownership contract, regression evidence and reviewer acknowledgment in the PR. For a lint exception use a local rule-specific disable comment containing that rationale and link to its review; do not weaken the global gate, hide the code from test discovery or add a legacy baseline. A platform permission/file picker already allowed above needs no exception.
